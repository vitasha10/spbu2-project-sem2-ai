# Прогнозирование отмены бронирования отеля

Проект по курсу «Технологии ИИ», СПбГУ, 2 курс, весна 2026.

Команда: Сухоплечев Виталий, Столярова Полина.

## Задача

Бинарная классификация: по параметрам брони предсказать, будет ли она отменена до заезда.

Целевая переменная — `is_canceled`. Основная метрика — ROC-AUC, дополнительные — F1-мера и полнота по классу «отмена».

## Данные

Hotel Booking Demand (Antonio, Almeida, Nunes, 2019), 119 390 записей по двум отелям Португалии за 2015 – 2017 годы. После чистки остаётся 86 970 строк, доля отмен — 27 %.

Файл `data/hotels.csv` в git не лежит, скачивается отдельной командой при первом запуске.

## Запуск

Самый простой способ — двойной клик по `run_all.bat`. Скрипт:

1. ставит зависимости через `pip install -r requirements.txt`,
2. скачивает датасет, если его ещё нет,
3. прогоняет все 5 ноутбуков (если ещё не построен `models/final_model.pkl`),
4. запускает Streamlit-приложение на `http://localhost:8501`.

Если зависимости и модель уже стоят, для запуска только приложения достаточно `run_app.bat`.

Ноутбуки выполняются в порядке: `01_eda.ipynb` → `02_preprocessing.ipynb` → `03_baseline.ipynb` → `04_models.ipynb` → `05_error_analysis.ipynb`. Каждый сохраняет промежуточные артефакты в `models/`.

## Структура

- `notebooks/` — пять ноутбуков по этапам работы (EDA, препроцессинг, бейзлайн, модели, анализ ошибок).
- `src/` — общий код: `data.py` (чистка) и `features.py` (новые признаки и колонки для пайплайна).
- `app/app.py` — Streamlit-приложение с готовыми сценариями.
- `models/` — сохранённые пайплайны (создаются при прогонке ноутбуков, в git не входят).
- `scripts/` — служебные скрипты для пересборки ноутбуков, презентации и отчёта.
- `report.docx` — отчёт по проекту со всеми обязательными секциями.
- `design_document.md` — то же содержание в формате markdown.
- `docs/presentation.pptx` — презентация на защиту.

## Результаты

Финальная модель — HistGradientBoostingClassifier. ROC-AUC на отложенном тесте — 0.917, F1-мера по классу «отмена» — 0.77, полнота — 0.67.

Подробности по этапам, метрикам и анализу ошибок — в `report.docx`.
